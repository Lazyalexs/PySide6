# FilePost — клиент

Настольный клиент для станций. Реализация этапов 3–4 из `architecture (1).md`.

## Главное правило

**Человек не вводит ничего, кроме кода регистрации при установке.** Ни логина,
ни пароля, ни адреса сервера, ни имени машины. Формы входа в системе нет вообще:
клиент авторизуется ключом станции сам при каждом запуске.

## Установка

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m filepost_client.main
```

При первом запуске откроется единственное окно, где что-то вводится: адрес сервера,
код регистрации от администратора и название станции («Бухгалтерия, окно 2»).
Дальше клиент работает сам.

## Сборка `.exe`

```
pyinstaller filepost.spec
```

Результат — `dist\FilePost.exe`. Устанавливается в `%LOCALAPPDATA%`, автозапуск
прописывается ключом реестра `Run` при первом старте (если включён в настройках).

## Слои

Зависимость строго однонаправленная: **UI → Core → ApiClient**. UI ничего не знает
про HTTP, Core — про виджеты. Благодаря этому ядро проверяется автотестами против
настоящего сервера, без запуска окон.

| Модуль | Назначение |
|---|---|
| `settings.py` | `config.ini`: параметры развёртывания и предпочтения |
| `api.py` | Единственный слой, знающий про HTTP; наружу — доменные исключения |
| `store.py` | `client.db`: кэш сообщений, очередь передач, курсор событий |
| `transfers.py` | Очередь в потоках, докачка, sha256, фаза «Проверка» |
| `core.py` | Фасад: подключение, синхронизация, отправка, приём |
| `discovery.py` | UDP-автопоиск сервера (крайняя мера, по умолчанию выключен) |
| `ui/` | PySide6: главное окно, отправка, передачи, станции, настройки, админка |

## Что где лежит

```
%LOCALAPPDATA%\FilePost\
├── client.db      кэш сообщений, очередь передач, last_event_id
├── downloads\     полученные файлы
├── partial\       незавершённые .part
├── logs\client.log
└── config.ini     параметры развёртывания и настройки
```

Отображаемое имя здесь **не хранится** — оно живёт на сервере, иначе на каждой
станции был бы свой набор имён.

## Тесты

```
python -m pytest tests/ -q
```

29 тестов. Ядро (17) поднимает настоящий сервер в потоке и гоняет полный цикл:
регистрацию, передачу, докачку с `Range`, переживание перезапуска, пересинхронизацию
после отката БД сервера, работу без связи. Интерфейс (12) проверяется на
offscreen-платформе Qt: окна строятся и наполняются настоящими данными.

## Поведение, которое легко потерять при доработках

- **Курсор событий сохраняется только после применения событий.** Иначе падение между
  двумя операциями теряет письмо.
- **Очередь передач живёт в `client.db`, а не в памяти.** Закрыли приложение на середине
  пятигигабайтной заливки — после запуска она продолжится.
- **`507` — не ошибка сети.** Повторять с нарастающей паузой бессмысленно: задание встаёт
  с текстом «На сервере нет места, обратитесь к администратору».
- **Фаза «Проверка» показывается отдельно.** Без неё пользователь видит замерший на 100 %
  индикатор и жмёт «Отменить» ровно перед успешным завершением.
- **Закрытие окна сворачивает в трей и не прерывает передачи.**
- **Автоскачивание выключено по умолчанию.** При гигабайтных файлах решение принимает человек.

## Не реализовано

- Ограничение скорости отдачи — настройка есть, троттлинг в `TransferManager` не подключён.
- Звук уведомлений — флаг есть, звук не проигрывается.
- Черновики: сообщение создаётся сразу на сервере, локальных черновиков нет.
