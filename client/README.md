# FilePost — клиент

Настольный клиент для станций. Реализация этапов 3–4 из `architecture (1).md`.

## Главное правило

**Человек не вводит ничего, кроме кода регистрации при установке.** Ни логина,
ни пароля, ни адреса сервера, ни имени машины. Формы входа в системе нет вообще:
клиент авторизуется ключом станции сам при каждом запуске.

## Установка

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m filepost_client.main
```

При первом запуске откроется единственное окно, где что-то вводится: адрес сервера,
код регистрации от администратора и название станции («Бухгалтерия, окно 2»).
Дальше клиент работает сам.

## Сборка `.exe`

```
pyinstaller filepost.spec
```

Результат — `dist\FilePost.exe`. Устанавливается в `%LOCALAPPDATA%`, автозапуск
прописывается ключом реестра `Run` при первом старте (если включён в настройках).

## Слои

Зависимость строго однонаправленная: **UI → Core → ApiClient**. UI ничего не знает
про HTTP, Core — про виджеты. Благодаря этому ядро проверяется автотестами против
настоящего сервера, без запуска окон.

| Модуль | Назначение |
|---|---|
| `settings.py` | `config.ini`: параметры развёртывания и предпочтения |
| `api.py` | Единственный слой, знающий про HTTP; наружу — доменные исключения |
| `store.py` | `client.db`: кэш сообщений, очередь передач, курсор событий |
| `transfers.py` | Очередь в потоках, докачка, sha256, фаза «Проверка», ограничение скорости |
| `sound.py` | Звук уведомлений через `winsound` (WAV, без QtMultimedia в сборке) |
| `core.py` | Фасад: подключение, синхронизация, отправка, приём, черновики |
| `discovery.py` | UDP-автопоиск сервера (крайняя мера, по умолчанию выключен) |
| `ui/` | PySide6: главное окно, отправка, передачи, станции, настройки, админка |

## Что где лежит

```
%LOCALAPPDATA%\FilePost\
├── client.db      кэш сообщений, очередь передач, last_event_id
├── downloads\     полученные файлы
├── partial\       незавершённые .part
├── logs\client.log
└── config.ini     параметры развёртывания и настройки
```

Отображаемое имя здесь **не хранится** — оно живёт на сервере, иначе на каждой
станции был бы свой набор имён.

## Тесты

```
python -m pytest tests/ -q
```

52 теста. Ядро поднимает настоящий сервер в потоке и гоняет полный цикл: регистрацию,
передачу, докачку с `Range`, переживание перезапуска, пересинхронизацию после отката БД
сервера, работу без связи. Интерфейс проверяется на offscreen-платформе Qt: окна строятся
и наполняются настоящими данными. Отдельно — ограничение скорости, звук и черновики.

## Поведение, которое легко потерять при доработках

- **Курсор событий сохраняется только после применения событий.** Иначе падение между
  двумя операциями теряет письмо.
- **Очередь передач живёт в `client.db`, а не в памяти.** Закрыли приложение на середине
  пятигигабайтной заливки — после запуска она продолжится.
- **`507` — не ошибка сети.** Повторять с нарастающей паузой бессмысленно: задание встаёт
  с текстом «На сервере нет места, обратитесь к администратору».
- **Фаза «Проверка» показывается отдельно.** Без неё пользователь видит замерший на 100 %
  индикатор и жмёт «Отменить» ровно перед успешным завершением.
- **Закрытие окна сворачивает в трей и не прерывает передачи.**
- **Автоскачивание выключено по умолчанию.** При гигабайтных файлах решение принимает человек.
- **Черновик живёт только локально.** На сервере сообщение создаётся в момент отправки,
  не раньше — поэтому письмо можно начать писать без связи.
- **Ограничение скорости общее на все потоки.** Ограничивать нужно канал, а не каждую
  передачу по отдельности.

## Звук уведомлений

Лежит в `filepost_client/resources/`: `notify.wav` (используется, 0,5 с, 22 КБ)
и `notify-source.wav` (исходник, 3,19 с, 44,1 кГц стерео). Играется через `winsound`
из стандартной библиотеки — только WAV, зато без QtMultimedia, который раздул бы `.exe`
в несколько раз ради одного короткого сигнала. Вне Windows звук молча не воспроизводится.

**Взяты первые 0,5 секунды исходника.** В них укладываются обе ноты сигнала — первая
на 0,000 с, вторая на 0,300 с; дальше в исходнике идёт затухающий хвост и почти две
секунды тишины. Уведомление, которое тянется три секунды на каждое входящее письмо,
выключают в первый же день.

Пересобрать из исходника:

```
ffmpeg -i filepost_client/resources/notify-source.wav \
       -t 0.5 -af "volume=0.5,afade=t=out:st=0.40:d=0.10" \
       -ac 1 -ar 22050 -acodec pcm_s16le filepost_client/resources/notify.wav
```

`afade` обязателен и не косметика: на 0,500 с сигнал ещё звучит на четверть шкалы,
и жёсткий рез там даёт отчётливый щелчок. Затухание за 0,1 с сажает конец в ноль —
последний отсчёт равен 1 при пике 15051.

Меняете исходник — посмотрите его огибающую и подберите `-t` и границу `afade` под него,
а не переносите эти числа вслепую. Два теста в `tests/test_extras.py` страхуют результат:
проверяют длительность и отсутствие разрыва на срезе.

## Не реализовано

- Оценка «примерно N минут» в окне отправки считается по размеру, а не по фактической
  скорости прошлых передач.
- Ограничение скорости применяется только к отдаче; приём не ограничивается.
