# FilePost — серверная часть

Реализация серверной части по `architecture (1).md`: БД, регистрация станций по коду,
авторизация ключом станции, чанковая загрузка с докачкой, скачивание с `Range`,
события и адресная книга, восстановление после сбоя, планировщик, резервное копирование.

Клиент — в каталоге `../client`.

## Установка

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

## Первый запуск

```
python -m filepost.cli --config config.toml init
```

Команда создаёт `config.toml` (если его нет), базу и **код регистрации первой станции**.
Код показывается один раз, действует 24 часа, станция по нему получает права
администратора. Дальше:

```
python -m filepost.cli --config config.toml serve
```

## Утилиты администратора

```
station list                 все станции, статус, версия клиента
station enroll [--admin]     выдать код регистрации новой станции
station reset <имя>          отозвать ключ, выдать новый код
station admin <имя>          выдать или снять права администратора
storage report               занято, свободно, ничейные, потерянные
storage verify               сверка БД и диска
db backup <путь>             корректный бэкап живой базы
db verify <файл>             проверка резервной копии
housekeeping [--backup]      разовый прогон уборки
```

`storage verify` **обязателен** после восстановления БД из копии: база и хранилище
после этого заведомо расходятся в обе стороны.

## Структура

| Модуль | Назначение |
|---|---|
| `config.py` | Загрузка `config.toml`, значения по умолчанию из 2.6 |
| `db.py` | Схема из 2.3, WAL, соединение на поток, корректный бэкап |
| `auth.py` | Коды регистрации, ключи станций, токены с TTL |
| `storage.py` | Резервирование места, чанки, сборка, sha256, `Range` |
| `messages.py` | Сообщения, вложения, статусы доставки, поиск ничейных |
| `journal.py` | События для синхронизации и аудит-журнал |
| `recovery.py` | Процедура старта из 2.12 и сверка хранилища |
| `housekeeper.py` | Уборка `tmp\`, обрезка событий, ночной бэкап, очистка по сроку |
| `discovery.py` | UDP-ответчик автопоиска (по умолчанию выключен) |
| `app.py` | FastAPI: endpoint'ы из 2.4 |
| `cli.py` | `init`, `serve`, `station`, `storage`, `db`, `housekeeping` |

## Тесты

```
python -m pytest tests/ -q
```

60 тестов: полный цикл передачи, докачка после обрыва, `Range`, несовпадение
контрольной суммы, идемпотентность `commit`/`send`/чанков, резервирование места,
восстановление после сбоя во всех трёх точках разрыва, двусторонняя проверка курсора
событий, планировщик и ротация бэкапов, права администратора.

## Установка службы

```
install-service.cmd
```

Ставит службу через NSSM (положите `nssm.exe` рядом), настраивает автозапуск,
перезапуск при падении, ротацию журналов и правило брандмауэра с `profile=any`.

## Что осталось до боевого запуска

- Исключение антивируса для каталога хранилища — согласовывается отдельно, скриптом
  не делается.
- Зеркальный том под `storage\`: файлы не бэкапятся осознанно, от смерти диска
  защищает только зеркало (2.13).
- `[backup] path` должен указывать на **другой физический диск**.

## Замечания по переносу на Windows

- Пути в `config.toml` пишутся с двойными обратными слэшами.
- `storage` и `tmp` **обязаны быть на одном томе**: финальное перемещение делается
  через `os.replace`, и между томами это будет копирование гигабайтов, а не мгновенный
  `rename`.
- `storage_path` в БД хранится с обратными слэшами, при чтении нормализуется —
  база, снятая на Windows, читается и на Linux.
