# Развёртывание FilePost

Пошагово, для администратора. Ничего, кроме двух установщиков, скачивать не нужно:
Python и прочие зависимости на целевых машинах не требуются.

Скачать: **[Releases](https://github.com/Lazyalexs/PySide6/releases/latest)**

- `FilePost-Server-Setup-1.0.3.exe` — на сервер, один раз
- `FilePost-Setup-1.0.3.exe` — на каждую станцию

---

## Шаг 1. Подготовка сервера

**Статический IP.** От него зависит вся адресация: если адрес однажды сменится сам,
связь потеряют разом все станции, и лечиться это будет обходом машин руками.

Задать в: Параметры сети → Настройка параметров адаптера → свойства адаптера →
IP версии 4 → «Использовать следующий IP-адрес». Либо резервация по MAC на DHCP.

Запишите адрес — он понадобится на каждой станции. Дальше в примерах `10.10.10.5`.

---

## Шаг 2. Установка сервера

Сервер **не нужно запускать** — установщик регистрирует его как службу Windows.
Служба стартует сама при включении машины и работает без входа пользователя.

1. Правой кнопкой по `FilePost-Server-Setup-1.0.3.exe` → **Запуск от имени
   администратора**. Без этого не получится: служба и правило брандмауэра требуют прав.

2. Windows покажет синее окно «Система Windows защитила ваш компьютер» — установщик
   не подписан сертификатом. Нажмите **«Подробнее»** → **«Выполнить в любом случае»**.

3. Каталог установки. По умолчанию `D:\FilePost`. **Если диска `D:` нет — поменяйте
   на `C:\FilePost`.** Пути в настройках подставятся под выбранный каталог сами.

   Здесь будут лежать и файлы пользователей, поэтому выбирайте том, где есть место.

4. **Порт службы.** По умолчанию `50067` — намеренно непопулярный: на 8080
   обычно уже что-то работает, и он первым попадает под сканеры.

   Установщик предупредит, что порт лежит в динамическом диапазоне Windows
   (49152–65535), откуда система раздаёт порты исходящим соединениям.
   Это нормально: он тут же зарезервирует порт за службой. Без резервирования
   служба **иногда** не стартовала бы после перезагрузки — плавающий отказ,
   который ищут долго.

   Если хотите порт без резервирования, возьмите ниже 49152, например `41067`.

5. Три галочки — оставьте все включёнными:
   - открыть выбранный порт в брандмауэре Windows;
   - исключить хранилище из проверки Defender (иначе скорость режется в разы);
   - зарегистрировать и запустить службу.

6. **Страница «Средства защиты».** Установщик проверит, стоят ли на машине
   Kaspersky и ViPNet, и покажет точный список того, что придётся настроить
   руками. **Прочитайте её** — без этих настроек система работать не будет
   (ViPNet) или будет работать медленно (Kaspersky). Подробности ниже.

7. **Предпоследняя страница покажет код регистрации первой станции.**
   Запишите его: он показывается один раз и действует 24 часа.

   Если пропустили — код лежит в файле `C:\FilePost\logs\enrollment-code.txt`.

Всё, сервер работает.

### Проверить, что работает

Откройте на сервере в браузере:

```
http://localhost:50067/api/health
```

Должно ответить строкой вида `{"status":"ok", ...}`.

Или посмотрите службу: `Win+R` → `services.msc` → **FilePost** → состояние
«Выполняется».

С другой машины сети проверьте, что сервер виден:

```
http://10.10.10.5:50067/api/health
```

Не отвечает — смотрите «Если что-то не работает» внизу.

## Шаг 2а. Kaspersky и ViPNet

Установщик их только обнаруживает и подсказывает — настроить за вас он не может:
оба управляются своими консолями, а в корпоративной сборке ещё и политикой.

### Kaspersky

**Исключение Microsoft Defender, которое ставит установщик, здесь бесполезно:**
при установленном Касперском Defender отключён.

В консоли Касперского заведите два исключения — только каталога или только
процесса недостаточно:

| Что | Значение |
|---|---|
| Доверенная папка | `C:\FilePost` |
| Доверенный процесс | `C:\FilePost\filepost-server.exe` |

Без этого каждый принимаемый чанк проверяется при записи, и скорость падает
в разы. На гигабайтных файлах это заметно сразу.

Проверьте также **«Защиту от сетевых атак»**: массовая передача на нестандартный
порт может выглядеть для неё подозрительно. Если передачи обрываются без причины
и в журнале сервера пусто — смотрите отчёты Касперского.

В корпоративной сборке это обычно закрыто политикой Kaspersky Security Center
и делается через администратора антивируса, а не локально на сервере.

### ViPNet

**Это важнее всего остального.** У ViPNet собственный сетевой экран, и он
фильтрует трафик **раньше** брандмауэра Windows. Правила, которое создаёт
установщик, недостаточно: станции просто не увидят сервер.

Что сделать:

1. В консоли ViPNet разрешить **входящий TCP на порт 50067** для сервера.
2. Проверить, каким адресом станции видят сервер. Если они работают через
   защищённую сеть ViPNet, адресом сервера будет его **адрес в сети ViPNet**,
   а не обычный IP из `ipconfig`. Именно этот адрес нужно вводить в клиенте.

**Про скорость.** ViPNet шифрует каждый пакет, поэтому реальная пропускная
способность будет заметно ниже гигабита. Оценка «5 ГБ за минуту» относится
к чистой сети; через ViPNet рассчитывайте на большее время. Клиент это учитывает:
он показывает «примерно N минут» по фактической скорости прошлых передач,
а не по паспортной скорости канала.

Если после настройки станция всё равно не видит сервер, проверяйте по порядку:

```
netstat -ano | findstr :50067     на сервере: слушает ли служба
```

Затем с сервера `http://localhost:50067/api/health` — если отвечает, дело
в сети, и это либо ViPNet, либо профиль брандмауэра Windows.

## Шаг 3. Первая станция — рабочее место администратора

Ставьте на ту машину, с которой будете управлять системой: она получит права
администратора и с неё выдаются коды остальным.

1. Запустите `FilePost-Setup-1.0.3.exe`. Прав администратора **не требует**.
2. Тот же экран SmartScreen → «Подробнее» → «Выполнить в любом случае».
3. После установки клиент откроет окно первоначальной настройки:

   | Поле | Что вводить |
   |---|---|
   | Адрес сервера | `10.10.10.5:50067` |
   | Код регистрации | тот, что записали на шаге 2 |
   | Название станции | «Бухгалтерия, окно 2» — так вас увидят остальные |

4. Нажмите «Зарегистрировать».

Больше ничего вводить не придётся никогда: клиент запоминает ключ станции
и дальше входит сам.

---

## Шаг 4. Остальные станции

Для каждой нужен **свой** код: они одноразовые.

**Способ 1 — из клиента администратора.** Раздел **Управление → Станции →
«Добавить станцию»**. Код появится внизу окна.

**Способ 2 — из консоли сервера.** Работает всегда, даже если админская станция
недоступна:

```
cd C:\FilePost
filepost-server.exe --config config.toml station enroll
```

Дальше на станции — как в шаге 3.

### Установка без вопросов

Если ставите на семь машин подряд, адрес и название можно задать сразу:

```
FilePost-Setup-1.0.3.exe /VERYSILENT /SERVER=10.10.10.5:50067 /STATION="Склад"
```

Тогда пользователю останется ввести только код регистрации.

## Шаг 5. Проверка

С одной станции отправьте файл на другую: **Новое сообщение** → выберите получателя
из списка → перетащите файл → «Отправить». На второй станции файл должен появиться
во «Входящих» в течение 15 секунд.

## После установки: три вещи, о которых легко забыть

**1. Резервное копирование базы.** Откройте `C:\FilePost\config.toml`, найдите
`[backup]` и укажите путь **на другом физическом диске**:

```toml
[backup]
enabled = true
path = 'E:\Backup\FilePost'
```

Одинарные кавычки здесь не случайность: в двойных обратный слэш означает
экранирование, и путь Windows пришлось бы писать с удвоенными слэшами.
По умолчанию бэкап выключен — включите, когда укажете путь.

Копия рядом с оригиналом защищает только от случайного удаления и бесполезна
в том, ради чего бэкап делается.

Бэкапится только база (30–50 МБ в год), файлы пользователей — нет. Но без базы
файлы бесполезны: на диске лежат `a3f2c1e4-….bin`, а кто кому что отправил, знает
только база.

**2. Файлы не бэкапятся — от смерти диска защищает только зеркало.** Если данные
критичны, поставьте хранилище на зеркальный том (RAID-1).

**3. Место на диске кончится.** Автоочистка выключена: ничего не удаляется само.
Когда свободное место упадёт ниже порога, приём новых файлов заблокируется.
Следите в клиенте: **Управление → Хранилище**. Там же удаляются ничейные файлы —
те, что скрыли у себя все участники; их удаление никто не заметит.

## Если что-то не работает

**Служба не запустилась.** Посмотрите `C:\FilePost\logs\app.log` и
`C:\FilePost\logs\service.log` — там будет причина. Запустить вручную:
`net start FilePost`, остановить: `net stop FilePost`.

**Сервер отвечает на самом сервере, но не виден с других машин.** Две причины
по убыванию вероятности.

Первая — **ViPNet**: его экран фильтрует раньше Windows, разрешите порт в его
консоли (шаг 2а).

Вторая — правило брандмауэра Windows создано не для того профиля. Сеть без
домена Windows обычно относит к «Общедоступной», а правило по привычке создают
для «Частной». Проверьте:

```
netsh advfirewall firewall show rule name="FilePost HTTP"
```

**Клиент пишет «Нет связи с сервером».** Проверьте адрес: он должен быть виден
в браузере со станции по `http://адрес:50067/api/health`. Технические сведения —
в клиенте: **Настройки → Диагностика**, кнопка «Скопировать сведения».

**Код регистрации не принимается.** Он одноразовый и живёт 24 часа. Выдайте новый
(шаг 4).

**Переустановили ПК станции.** Не заводите её заново — сбросьте ключ, из клиента
администратора («Управление → Станции → Сбросить ключ») или из консоли сервера:

```
filepost-server.exe --config config.toml station reset "Склад"
```

Полученный код привязан к этой станции: клиент, зарегистрированный по нему,
получит её имя, входящие и историю переписки. Обычный код (`station enroll`)
завёл бы вторую станцию, а письма, отправленные до переустановки, остались бы
на строке, к которой уже никто не подключается.

**Потерян доступ администратора** — например, админскую станцию переустановили,
а сбросить ключ теперь некому. Из консоли сервера:

```
filepost-server.exe --config config.toml station enroll --admin
```

**Служба иногда не стартует после перезагрузки.** Порт из динамического
диапазона занят исходящим соединением. Проверьте резервирование:

```
netsh int ipv4 show excludedportrange protocol=tcp
```

Порта 50067 нет в списке — добавьте:

```
netsh int ipv4 add excludedportrange protocol=tcp startport=50067 numberofports=1
```

**Передачи обрываются, а в журнале сервера пусто.** Смотрите отчёты Касперского:
скорее всего сработала «Защита от сетевых атак».

**Файл не докачивается.** Так и должно быть при обрыве: передача продолжается сама
и переживает перезапуск клиента. Смотрите вкладку «Передачи» — там видно состояние
и причину, если это ошибка.
